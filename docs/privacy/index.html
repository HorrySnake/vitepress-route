隐私说明Privacy notice

版本 0.1 · 草案更新于 2026 年 10 月 1 日 · 尚未生效Version 0.1 · Draft updated October 1, 2026 · Not yet effective
这是开发阶段草案，用于说明计划中的产品行为。发布前需确认运营主体、联系方式及实际数据处理方式；本草案不是已生效的法律条款。This development-stage draft describes planned product behavior. The operator, contact details, and actual data practices must be confirmed before release. This draft is not an effective legal agreement.

1. 适用范围与运营主体1. Scope and operator

本草案覆盖 Route iOS App 的计划数据处理方式。运营主体与隐私联系渠道尚待确定，正式发布前将补充。网站托管的数据处理与 App 请求链路不同。This draft covers planned data practices for the Route iOS app. The operator and privacy contact are not yet finalized and will be added before release. Website hosting is separate from the app’s request flow.

2. API Key 与配置2. API keys and configuration

设计目标是将 API Key 保存在设备 Apple Keychain 中，不写入快捷指令、内容日志或分析事件，不向开发者服务器上传。Profile 与模型配置计划在本地管理；同步、备份和卸载后的行为需按最终实现确认。The design goal is to store API keys in Apple Keychain on the device, exclude them from shortcuts, content logs, and analytics events, and avoid uploading them to developer servers. Profiles and model settings are planned to be managed locally; sync, backup, and uninstall behavior must be confirmed against the final implementation.

3. AI 请求发送到哪里3. Where AI requests go

发起操作时，所选服务将接收完成任务所需的输入、提示词与模型参数，以及用于认证的 Key。计划采用设备直连 Provider。图片、文件或个人信息只应在你确认相应输入并允许发送后交给所选服务。When an action runs, the selected service receives the input, prompt, and model parameters needed for the task, together with the key used for authentication. Direct device-to-provider requests are planned. Images, files, or personal information should be sent only after you confirm the relevant input and authorize its transmission.

4. 第三方服务4. Third-party services

你所选择的 Provider 或自定义 Endpoint 有独立的数据处理规则，包括保留时间、存储地区与训练用途。使用前请阅读该服务的政策。Route 的本地保存目标不代表 AI 服务不保存请求；启用未来的 Fallback 时，也需明确额外接收方。The provider or custom endpoint you choose has its own data practices, including retention, storage location, and training use. Read its policies before use. Route’s local-storage goal does not mean the AI service retains no requests. Future fallback features must also make additional recipients clear.

5. 使用记录与分析5. Usage records and analytics

Token 与费用统计是未来方向。是否保存调用元数据、保留多久、是否使用崩溃或分析 SDK 尚未确定。正式政策将逐项披露；不以开发计划作为“不收集任何数据”的承诺。Token and cost statistics are a future direction. Storage of call metadata, retention periods, and use of crash or analytics SDKs are not finalized. The effective policy will disclose each item; development plans are not a promise of zero data collection.

6. 网站访问6. Website visits

此网站不包含注册、API Key 输入或内容上传。语言选择使用浏览器本地存储。页面访问会向托管服务发送通常的网络请求信息；托管平台的日志与保留规则应在公开上线前核实。This website has no registration, API-key entry, or content-upload form. Language preference uses browser local storage. Page visits send ordinary network-request information to the hosting service; its logging and retention practices should be verified before public launch.

7. 删除、权限与联系7. Deletion, permissions, and contact

计划允许用户在 App 中删除 Key 与 Profile，并通过系统管理相关权限。删除本地配置不会自动删除 Provider 已收到的数据。数据请求与问题反馈需使用正式发布时公布的联系渠道。Users are intended to be able to delete keys and profiles in the app and manage relevant permissions through the system. Deleting local settings does not automatically delete data already received by a provider. Data requests and questions should use the contact channel published at release.

8. 正式发布前的确认8. Before release

需补齐：运营主体、联系渠道、生效日期、实际 SDK 清单、数据保留与删除规则、同步备份行为、适用地区与第三方处理说明。任何变更都应与 App 的实际行为及 App Store 隐私披露保持一致。Finalize the operator, contact channel, effective date, actual SDK list, retention and deletion rules, sync and backup behavior, applicable regions, and third-party processing disclosures. Changes should remain consistent with actual app behavior and App Store privacy disclosures.
